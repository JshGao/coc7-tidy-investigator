## 1. 目标与非目标

### 1.1 目标

1. 视觉明显优于 CoC7 v3 默认卡：干净、留白、信息密度高、扫读快，继承 Tidy 5e 的"金/灰双色板 + 徽章 + 表格行 + 悬停操作"语言。
2. 交互减少层级：技能/特性**点一下即投骰**，数值**点一下即改**，操作按钮**悬停即现**。
3. 功能**完整覆盖** v3 默认调查员卡的日常使用（见 §7 对照表），不因换皮缺功能。
4. 纯前端、可自行修改：无打包、文件清晰、CSS 变量可覆写。
5. 与系统默认卡、ginzzzu 等第三方卡**并存**，不冲突。

### 1.2 非目标

- 不做 NPC / 生物 / 载具 / 容器卡（v1）。生物 / NPC 卡已在 v0.8 规划中，见 [04-生物卡设计文档](./04-生物卡设计文档.md)；载具 / 容器仍不做。
- 不改写 CoC7 规则计算（HP/DB/成长等一律用系统派生值）。
- 不做移动端专门布局（但窗口缩到最小宽度不崩）。
- 不美化物品卡（v2 可选）。
- 不处理 Babele 翻译包逻辑，只做 i18n。

## 3. 布局方案（已选定：方案 A）

> 调研纠正：Tidy 5e 真实布局并不是"左侧能力值面板 + 右侧 tab"。它的**特性/能力值横排在顶部横幅里**，左侧是**可收起的收藏/技能二级栏**。因此有三个可选骨架：

### 方案 A：忠实 Tidy（顶部横幅）✅ 已选用

```
┌────────────────────────────────────────────────────────────────────────┐
│ 横幅 200px：深色渐变 + 羊皮纸纹理 + 金色底边                            │
│ ┌─────────┐  埃莉诺·万斯                          [锁/编辑] [效果] [⋯]  │
│ │ 头像    │  记者 · 32岁 · 女 · 波士顿                                  │
│ │ 152×152 │                                                            │
│ └─────────┘  ┌────┬────┬────┬────┬────┬────┬────┬────┐                 │
│              │STR │CON │SIZ │DEX │APP │INT │POW │EDU │  8 特性横排      │
│              │ 60 │ 55 │ 55 │ 65 │ 45 │ 70 │ 50 │ 75 │                  │
│              └────┴────┴────┴────┴────┴────┴────┴────┘                 │
│  ┌──────┬──────┬──────┬──────┬──────┬──────┐   HP/MP/SAN/LUCK 方块     │
│  │HP 12 │MP 10 │SAN 55│LCK 60│DB 0  │MOV 8 │   （压在下缘的深色条）     │
│  └──────┴──────┴──────┴──────┴──────┴──────┘                            │
│  ●重伤 ●昏迷 ○濒死 ○死亡 ○倒地 ○临时疯狂 ○长期疯狂                      │
│  [ 技能 ][ 简表 ][ 物品 ][ 背景 ][ 成长 ][ 笔记 ][ 效果 ]  ← tab 行     │
├──────┬─────────────────────────────────────────────────────────────────┤
│ 侧栏 │ 主内容（全宽，表格列充足）                                        │
│ 收藏 │ ┌───────────────────────────────────────────────────────────┐   │
│ (可  │ │ 技能表 …                                                  │   │
│ 收起)│ └───────────────────────────────────────────────────────────┘   │
└──────┴─────────────────────────────────────────────────────────────────┘
```

- 优点：最像 Tidy；主区全宽，60+ 技能/武器表列得下；状态与资源永远可见。
- 缺点：横幅占高 ~200px（可用折叠按钮收起），窄窗时需降级。

### 方案 B：左栏常驻（未采用，保留备查）

```
┌──────────────────────────────────────────────────────────────────┐
│ [头像] 姓名 + 副标题 + 锁定按钮                                    │
├──────────┬───────────────────────────────────────────────────────┤
│ 左栏300px │ [技能][简表][物品][背景][成长][笔记][效果]             │
│ 特性4×2   │ ┌───────────────────────────────────────────────────┐ │
│ HP/MP/    │ │ 技能表（可用宽度 ≈760px）                          │ │
│ SAN/LCK   │ │                                                   │ │
│ 派生值    │ │                                                   │ │
│ 状态芯片  │ └───────────────────────────────────────────────────┘ │
└──────────┴───────────────────────────────────────────────────────┘
```

- 优点：特性/资源常驻且大，适合频繁查看与投骰；实现简单。
- 缺点：不像 Tidy；主区变窄，武器表需隐藏次要列。

### 方案 C：混合（未采用，保留备查）

顶部只放"头像 + 姓名 + HP/MP/SAN/LCK 四联 + 状态"（高 ~110px），8 特性 4×2 与派生值放左栏（260px），主区右侧 tab。

- 优点：资源与状态永远可见，特性区面积大；横幅比 A 矮。
- 缺点：仍非 Tidy 原生骨架，主区宽度折中。

> **结论（已确认）**：采用**方案 A**。侧栏默认收起，展开后为「收藏/常用」列表（星标置顶技能与武器）。

### 3.1 窗口与响应式

- 默认 **780×780**（实测观感最合适），可**四边/四角八向缩放**，最小 700×500。
- 窄宽度适配：`<820px` 时侧栏收窄到 188px；内容区 `<520px` 时隐藏「基础」列，保证技能名完整。
- 横幅约 330px（头像 132 + 特性 86 + 资源行 44 + 状态行 30 + tab 42）；780 高时内容区约 450px，可显示 ~12 行技能。
- 全部尺寸用 `rem` + container query；不在根节点写死 `min-width`。
- 横幅可整体折叠（记忆），折叠后只留一行姓名与资源。

## 4. 视觉规范

### 4.1 CSS 变量分层

```
.coc7-tidy
  ├─ 调色板    --c7t-palette-*      （金/灰/语义色）
  ├─ 语义      --c7t-color-*        （bg/panel/border/text/accent/san/luck/hp/mp）
  ├─ 尺寸      --c7t-size-* / --c7t-radius-* / --c7t-shadow-* / --c7t-transition
  └─ 字体      --c7t-font-*
.themed.theme-light / .themed.theme-dark
  └─ 只覆盖语义层
```

强调色用 `oklch(from …)` 派生五级（照抄 Tidy 的换肤机制），一个 `--c7t-accent` 即可换整卡色相。

| `--c7t-panel-2` | `#f1ebe8` | `#303236` | 表头/次级底 |

### 4.3 字体（⏳ 待确认）

| Token | 值 | 用途 |
|---|---|---|
| `--c7t-font-title` | `"IM Fell English", "Songti SC", "Noto Serif SC", serif` | 角色名、tab 标题 |
| `--c7t-font-body` | `"Roboto Condensed", "PingFang SC", "Microsoft YaHei", sans-serif` | 表格、数值 |
| `--c7t-font-longform` | `"Signika Negative", "PingFang SC", sans-serif` | 富文本、备注 |

- 数字统一 `font-variant-numeric: tabular-nums`。
- 随包字体：Roboto Condensed（Apache-2.0）、Signika Negative（OFL）、IM Fell English（OFL），woff2 子集；中文不打包，回退系统字体。
- 字号阶梯：10/11/12/13/14/16/20/24px；基础 13px。

### 4.4 尺寸与形状

| 项 | 值 |
|---|---|
| 间距 | 2/4/6/8/12/16/24/32px（0.125rem 起） |
| 圆角 | 2px 小元素、3px 卡片主圆角、50% 圆徽章、头像 4px |
| 边框 | 1px 细线；强调 1px 金线 |
| 阴影 | 卡片 `0 0 .375rem #00000073`；浮层 `0 .25rem 1.5rem #00000040` |
| 过渡 | 全局 `150ms ease-in-out`（唯一值） |
| 行高 | 表格行 30px（紧凑 26px）；抬头 34px |

### 4.5 特性徽章（核心视觉，已定：自制 SVG）

- 形态：**盾形**（同 Tidy 的 ability badge），描金边、内填面板色。
- 内容：中央 20–22px 大号数值；下方 3 字母缩写（10px、字距 +0.05em）；底部微字 `半值 / 1/5值`。
- 交互：悬停金色发光 + 轻微上浮；左键投骰、右键对抗、Shift 快速投。
- AE 修正：右上角小标记，tooltip 提示"受效果影响"。
- 实现方式（已定）：**自制盾形 SVG**，`fill`/`stroke` 用 `currentColor` 与 CSS 变量，随主题自动着色；一个 SVG 内联进模板做 `<symbol>` 复用。

### 9.4 权限与编辑态

- `locked=true`（默认）：隐藏 `name=` 输入，数值纯文本；**点击特性徽章整体 = 投骰**。
- `locked=false`（解锁）：
  - 特性徽章：缩写标题与锁定态**完全一致**（不移动、不加装饰）；数值为 50px 宽输入框（不超出盾形），左/右/下三边为边框，**顶边为左右两段短线、中间留空**；点击缩写仍可投骰。
  - HP/MP/SAN/幸运 显示当前值与上限输入框；上限在 `auto=true` 时为只读（tooltip 说明）。
  - 派生值只保留 DB / 体格 / 移动力 / 护甲（横幅不再显示灵感/知识），编辑态均为输入框；DB/体格/移动力 在系统 `auto=true` 时只读（避免与自动计算冲突）。空字符串/`null` 统一显示为 `0`。
  - 每日 SAN 的「损失 / 上限」变为输入框。
  - 技能行显示删除按钮与可点击的成长勾选。
- 所有输入使用 `submitOnChange`，直接写回 CoC7 原生字段。
- 无 owner：limited 模板（姓名/头像/HP 状态）。
- GM：额外可见「笔记」tab；即使卡被锁也可编辑笔记内容（二次确认）。

### 10.3 投骰接入（已核对 8.16 签名）

```js
// 技能：传已存在 Item 的 name（skillCheck 会 getItemOrAdd 补建，避免传错字符串）
await actor.skillCheck(item.name, event.shiftKey, { event });
// 对抗
await actor.skillCheck(item.name, false, { event, cardType: "C/OP" });
// 特性 / 属性

await actor.attributeCheck("lck", event.shiftKey, { event });
// 武器
await actor.weaponCheck(weapon, event.shiftKey);
// 伤害（无公开 API，自建公式）
const range = weapon.system.range.normal;             // normal / long / extreme
const formula = applyDamageBonus(range.damage, actor); // 处理 DB（满值 / 半值）
await new Roll(formula, actor.parsedValues()).toMessage({ speaker: ChatMessage.getSpeaker({actor}) });
// 成长
await actor.developSkill(skill.id, event.shiftKey);
```

所有调用前统一能力探测（`typeof actor.skillCheck === "function"` 等），失败只提示不崩。

### 10.4 性能

- 多 PART：切 tab 只渲染对应 part；改数值只重渲 `sidebar`/`header`。
- 搜索/排序在 JS 完成，不触发全量 `_prepareContext`；保留输入光标。
- 折叠区未展开不渲染内部行。
- 列表项 `content-visibility:auto`（技能 >40 行时）。

### 10.5 兼容性守则

1. 每个注册独立 `try/catch`；错误在 `ready` 用 `permanent` 通知 GM。
2. schema 驱动枚举（`system.schema.getField("attribs")?.keys()`）；特征顺序读系统设置 `characteristicsOrder`。
3. 只用公开 Actor 方法；不碰 `actor.skills`（8.16 已会抛异常）。
4. 只写 CoC7 原生字段，自定义状态进 `flags["coc7-tidy-investigator"]`。
5. 尊重原始拼写（`developement`、`checkFailled`）。
6. AE 覆盖检测用 `foundry.utils.flattenObject(document.overrides)`。
7. 富文本入口三态回退（`TextEditor.implementation ?? TextEditor`）。
8. 模板不持有文档对象，只存 `_id`/`uuid`。
9. 不加系统 `.coc7` 类，选择器一律挂 `.coc7-tidy` 前缀。

## 15. 简表的技能分类（映射草案）

### 15.1 收录规则

- **只收录「非初始值」技能**：`system.adjustments.personal + occupation + archetype + experiencePackage + experience ≠ 0`（等价于 `valueUnmodified > adjustments.base`）。
- **战斗技能组例外**：默认显示全部战斗技能（闪避/格斗等基础值也常用），基础值项以弱化样式 + tooltip「未投入」区分。
- 工具栏「仅显示已投入」开关可统一切换（默认开）。
- 排序：类别内按当前值降序（与技能 tab 的「按数值」一致），可在设置中改为按名称。
- 未归类的技能（自制技能、翻译变体）进入「其他技能」组，排最后。
- 分类主键为 **CoC-ID**（`flags.CoC7.cocidFlag.id`，语言无关）；缺失 CoC-ID 时按名称回退匹配（内置中/英别名表）；仍无法归类则进「其他」。

### 15.3 展示形态

- 每个类别一行：左侧类别名 + 数量徽章，右侧自适应换行的**技能芯片**。
- 芯片内容：`技能名 + 当前值 + 半值/五分之一值`；点击投骰、右键对抗、Shift 快速投。
- 剑尖（专长）技能直接用 Item 名称（如「射击（手枪）」），不做二次分组。
- 芯片数量多时自动换行；类别为空则不显示（或显示「—」占位）。

## 16. 背景七要素与「关键链接」

### 16.1 七个固定条目

| slot id | 中文 | 系统对应 |
|---|---|---|
| `appearance` | 外貌形象 | `CoC7.InvestigatorWizard.PersonalDescription`（形象描述） |
| `beliefs` | 思想信念 | `rt..backstory-ideology-and-beliefs` |
| `treasured` | 宝贵之物 | `rt..backstory-treasured-possessions` |
| `locations` | 意义非凡之地 | `rt..backstory-meaningful-locations` |
| `people` | 重要之人 | `rt..backstory-significant-people` |
| `traits` | 特质 | `rt..backstory-traits` |
| `scars` | 伤疤和恐惧症 | `rt..backstory-injuries-and-scars`（伤害与疤痕）+ 恐惧症物品 |

- 卡片式布局：外貌形象整行；思想信念/宝贵之物、意义非凡之地/重要之人两两并排；特质、伤疤和恐惧症各占整行（伤疤卡内含恐惧症芯片区）。
- 底部保留「背景故事（`system.backstory`）」「遭遇记录（`system.notes` / `sanityLossEvents`）」。

### 16.2 数据存放

- **正文存 `system.biography[]`**（CoC7 原生 `{title, value}` 结构），切回系统默认卡仍可见、可编辑。
- 首次打开本卡时：按标题别名（中/英）匹配，缺失项自动补一条空段落；标题写入当前语言。
- 记录 `flags["coc7-tidy-investigator"].backgroundTitles = {appearance:"外貌形象", …}`，用于标题被改名后仍能定位。
- 额外自定义传记段落：仍用 `system.biography`，排在这七项之后，可增删/上下移动。

### 16.3 伤疤和恐惧症

- **纯文本背景设定**，与其余六项一样存 `system.biography` 的「伤疤和恐惧症」段（对应规则书的「伤害与疤痕」+ 恐惧症/狂热症描述）。
- 设计取舍：系统的 `status` 物品虽然支持恐惧症/狂热症（`system.type.phobia/mania`，可挂效果），但那是**游戏中掉 SAN 触发的状态**；本卡此栏记录的是**人物背景设定**，两者语义不同，因此不联动、不重复创建物品。
- 卡片内建议格式（仅作为编辑提示，不强制）：伤疤 / 恐惧症 / 狂热症 各一行。

### 16.4 关键链接

- 规则书建议选一项，但**游戏内存在多个关键链接的情形**，因此按**多选**实现。
- 存储：`flags["coc7-tidy-investigator"].keyConnections = ["beliefs","people"]`（slot id 数组，可为空）。
- 表现：被选中的卡片描边高亮 + 强调色标题 + 星标；背景页工具栏显示「★ 关键链接：思想信念、重要之人」，未选择时隐藏。
- 交互：勾选胶囊切换；工具栏摘要可点击定位到对应卡片。
- 兼容：其他模块/系统卡不识别该 flag 时无副作用。

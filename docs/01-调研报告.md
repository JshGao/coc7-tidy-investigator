## 1. CoC7 系统架构（8.16）

### 1.1 Actor 类型

`system.json → documentTypes.Actor`：`character`、`npc`、`creature`、`vehicle`、`container`。
Item 类型共 13 种：`archetype`、`armor`、`book`、`chase`、`experiencePackage`、`item`、`occupation`、`setup`、`skill`、`spell`、`status`、`talent`、`weapon`。

### 1.2 表（Sheet）体系：全部是 ApplicationV2

CoC7 8.16 已全面迁移到 **AppV2**：`class CoC7ModelsActorGlobalSheet extends HandlebarsApplicationMixin(foundry.applications.sheets.ActorSheetV2)`。
注册方式（`init` 钩子内）：

```js
Actors.unregisterSheet("core", foundry.appv1.sheets.ActorSheet);
Actors.registerSheet("CoC7", CoC7ModelsActorNPCSheetV2,     { types: ["npc"],       makeDefault: true, label: ... });
Actors.registerSheet("CoC7", CoC7ModelsActorVehicleSheetV2, { types: ["vehicle"],   makeDefault: true });
Actors.registerSheet("CoC7", CoC7ModelsActorCreatureSheetV2,{ types: ["creature"],  makeDefault: true });
Actors.registerSheet("CoC7", CoC7ModelsActorContainerSheetV2,{ types: ["container"],makeDefault: true });
// 调查员有 4 张卡可选：
Actors.registerSheet("CoC7", CoC7ModelsActorCharacterSheetV2,          { types:["character"] });
Actors.registerSheet("CoC7", CoC7ModelsActorCharacterSheetSummarizedV2,{ types:["character"] });
Actors.registerSheet("CoC7", CoC7ModelsActorCharacterSheetSummarizedV3,{ types:["character"] });
Actors.registerSheet("CoC7", CoC7ModelsActorCharacterSheetV3,          { types:["character"], makeDefault:true });
```

继承链：`CharacterSheetV3 extends CharacterSheetV2 extends GlobalSheet`；`SummarizedV3 extends SummarizedV2 extends CharacterSheetV2`。

- **默认卡 = `CoC7ModelsActorCharacterSheetV3`**（"CoC7 调查员角色卡 v3"），980×814，`classes:["investigator"]`。
- 另有 v2 / 精简 v3 两张可选卡。
- 第三方模块注册 `types:["character"]` 的 sheet 完全合法（ginzzzu 模块即如此），可与系统自带卡并存，由用户在"配置界面 → 角色卡"中切换。

### 1.3 character 数据模型（`CoC7ModelsActorCharacterSystem`）

| 路径 | 内容 |
|---|---|
| `system.characteristics.{str,con,siz,dex,app,int,pow,edu}` | 每项 `{value, formula}`；另有 AE 附加的 `bonusDice` |
| `system.attribs.hp` | `{value,max,auto}` |
| `system.attribs.mp` | `{value,max,auto}` |
| `system.attribs.lck` | `{value}` |
| `system.attribs.san` | `{value,max,dailyLoss,dailyLimit,auto}` |
| `system.attribs.mov` | `{value,auto,type}` |
| `system.attribs.db` | `{value,auto}`（伤害加成，字符串型） |
| `system.attribs.build` | `{value,auto}`（体格） |
| `system.attribs.armor` | `{value,notes}` |
| `system.conditions` | `criticalWounds / unconscious / dying / dead / prone / tempoInsane{value,realTime,duration} / indefInsane`，每项 `{value:boolean}` |
| `system.infos` | `occupation / age / sex / residence / birthplace / archetype / organization / playername` |
| `system.flags` | **`locked`（锁定/编辑）、`manualCredit`、`mythosHardened`、`mythosInsanityExperienced`、`skillListMode`、`skillShowUncommon`** |
| `system.monetary` | `{format, symbol, values:[{name,min,max,cashType,cashValue,assetsType,assetsValue,spendingType,spendingValue}]}` |
| `system.config` | 派生：`know{value,bonusDice}`、`idea{value,bonusDice}`、`naturalHealing` |
| `system.books` / `system.biography[]` / `system.backstory` / `system.notes` / `system.development` | 书籍进度 / 传记分段 / 背景故事 / 备注 / 发展点数 |
| `system.sanityLossEvents` | 疯狂遭遇记录 |

派生值在 `prepareBaseData/prepareDerivedData` 中计算（HPmax、MPmax、DB、Build、MOV、SANmax、灵感/知识等），模板直接读 `system.attribs.*` 即可，**不要自己重算**。

### 1.4 技能（skill）是 Actor 内嵌 Item

`system.skillName`、`system.specialization`（专长分组，如"格斗(斗殴)"）、`system.base`、`system.adjustments.{base,personal,occupation,archetype,experiencePackage,experience}`、`system.properties.*`、`system.flags.{archetype,developement,occupation,experiencePackage}`。
派生字段：`system.value`（总技能值）、`system.valueUnmodified`。
模板助手（系统已全局注册，可直接用）：`calcHard`（半值）、`calcExtreme`（五分之一值）、`percentValue`、`contains`、`selectValue`。

### 1.5 投骰 / 交互的公共 API（关键！）

CoC7 **没有**把 sheet 类或 `CoC7RollNormalize` 暴露到全局，但 **Actor 文档上有公开方法**，第三方 sheet 可以直接调用：

```js
await actor.skillCheck(skillItemOrName, fastForward, { event, poolModifier, difficulty, cardType });
await actor.characteristicCheck("str", fastForward, { event, ... });
await actor.attributeCheck("lck", fastForward, { event, ... });
await actor.weaponCheck(weaponItemOrData, fastForward);
await actor.developSkill(skillId, fastForward);     // 成长检定
```

- `cardType: "C/OP"` = 对抗检定；`"C/NO"` = 普通；`"C/CO"` = 组合；`"C/SC"` = SAN。
- `difficulty` 取 `CoC7DicePool.difficultyLevel.*`（regular/hard/extreme/critical）。
- `fastForward` / `options.event.shiftKey` = 跳过对话框直接投。
- 其他有用入口：`game.CoC7.macros.{skillCheck,weaponCheck,check}`、`game.CoC7.skillNames`、`game.CoC7.cocid`。

### 1.6 系统默认 v3 调查员卡的信息架构（功能基线）

`body.hbs` = 左侧 `aside.personal-details`（头像框 + 滚动区：传记 / 主特性 / 次属性 / 派生值）+ 右侧 `sheet-main`（tab 内容）。
Tab（`DEFAULT_OPTIONS.PARTS` + 系统模板）：

| tab | 内容 |
|---|---|
| background 背景 | 个人信息（姓名/年龄/性别/职业/出生地/居住地/原型/组织/玩家名）、背景故事、传记分段增删与排序、遭遇记录 |
| possessions 物品 | 武器 / 护甲 / 书籍 / 法术 / 天赋 / 物品 / 状态 分节 + 货币（信用评级/现金/资产/消费）+ 备注 + 幸运特殊用法按钮 |
| combat 战斗 | 近战技能与武器、远程技能与武器、掷伤害 |
| skills 技能 | 技能列表（按名称/数值排序、显示/隐藏罕见技能、成长标记、专长分组、半/五值） |
| activeEffects 效果 | Actor 的 ActiveEffect 列表 |
| development 发展（owner） | 个人/职业/原型/经验包点数分配 + 成长勾选 + 成长检定 |
| keeper 守秘（GM） | 货币配置、书籍进度、SAN 损失事件、清除状态、守秘笔记 |
| portraitConfig 头像配置 | 头像裁切方式 |

交互约定（我们的卡可沿用同名约定以复用系统行为/样式习惯）：

- 类名：`.rollable`、`.characteristic-name`、`.skill-name`、`.weapon-name`、`.attribute-name`、`.item`、`.item-control`、`.clickable`
- `data-characteristic`、`data-attrib`、`data-item-uuid`
- `data-action`：`auto-toggle`、`reset-counter`、`item-add/item-edit/item-delete`、`toggle-flag`、`weapon-damage`、`condition`、`monetary-*`、`biography-*` 等
- 点击掷骰 / 右键对抗 / Shift 快速投；`system.flags.locked` 控制只读。

### 1.7 本地化

`lang/` 有 `cn.json`、`zh-TW.json`、`en.json` 等 15 种。**本机 Foundry 语言 = `cn.foundry_chn`（中文）**，模块需提供中文 i18n。系统的键可直接复用（如 `CoC7.Skills`、`CoC7.HP`、`CoC7.SAN`）。

### 1.8 CSS

`system.css` 约 945KB（单行压缩）。**没有 `--coc7-*` 设计令牌体系**（该前缀只用于 journal/adventure 配色，34 处）；真正的主题变量挂在 `.application.coc7` 上，沿用 Foundry 的 `--color-*` 命名：

```css
.application.coc7{
  --color-hp-base:#922d2e; --color-mp-base:#101345;
  --color-san-base:#2e4b1f; --color-luck-base:#79501c;
  --color-labels-base:#922d2e; --color-warning:#ff6400;
  --investigator-sheet-primary-font: customSheetFont,"Modesto Condensed";
  --investigator-sheet-secondary-font: customSheetFont,"Lusitana";
  /* 纹样/相框/丝带均为 assets/images/sheet-v3/*.webp 位图 */
}
```
字体由系统从 Google Fonts 注入（Noto Sans / Voltaire / Lusitana），并给 `<body>` 加 `running-v14` 类。

**结论**：不依赖系统 v3 的样式类名与布局（冲突），新卡用独立前缀（`.coc7-tidy`）自带全部样式；
也**不给根节点加 `.coc7` 类** —— 系统有 1958 条 `.coc7` 选择器，会把我们的布局一起改掉。只使用 Foundry 核心变量。

### 1.9 兼容红线（务必遵守）

| 事项 | 说明 |
|---|---|
| core V1 sheet 已被注销 | CoC7 `init` 里 `unregisterSheet("core", foundry.appv1.sheets.ActorSheet)`，老式 `ActorSheet` 不可用 |
| `actor.skills` 会抛异常 | 8.16 已 `deprecated.noLongerAvailable(..., until:15)`；改用 `actor.items.filter(i=>i.type==="skill")` 或 `actor.system.skills`（仅 character） |
| 技能值不要直接写 `system.value` | `value` 是 getter＝Σ`adjustments.*`；编辑要改 `adjustments.{base,personal,occupation,archetype,experiencePackage,experience}` |
| 没有 `applyDamage` | 伤害入口是 `actor.dealDamage(amount,{armor,ignoreArmor})` |
| 没有 `Item#use()` | 武器走 `actor.weaponCheck()` / `actor.weaponRoll()` |
| 武器伤害卡是内部类 | `CoC7ChatDamage.createFromWeapon()` 不可从模块调用；直接掷伤害需自建公式 + `actor.parsedValues()` |
| `skillCheck(name)` 会补建技能 | 内部 `getItemOrAdd`，名字不存在时会新建/拉取 compendium；应传已存在 Item 的 `name` |
| AE 键改写 | `system.skills.i.skill.*` 会被改写为 `i>>skill>>…`；技能可被 AE 覆盖 `value`/`bonusDice`，此时 `valueUnmodified` 仍是原值 |

### 1.10 可用的 Actor 公共方法（已核对签名）

```js
actor.skillCheck(skillData, fastForward, {event, cardType, difficulty, poolModifier, flatDiceModifier, ...})
actor.characteristicCheck(key, fastForward, options)
actor.attributeCheck("lck"|"san"|…, fastForward, options)
actor.weaponCheck(weaponData, fastForward)   // weaponData: {uuid}|{id}|{name}
actor.weaponRoll(weaponItem, attackerUuid)   // 需有目标或 disregardNoTargets
actor.dealDamage(amount, {armor, ignoreArmor})
actor.setHp(v) / actor.setSan(v)             // 内含伤害/护甲/重伤规则
actor.toggleCondition(key) / conditionsSet([...]) / conditionsUnset([...])
actor.resetDailySanity()
actor.developSkill(skillId, shift) / developmentPhase(...) / developLuck(...)
actor.parsedValues()                         // @str/@hp/@db 等公式 token 上下文
```
`cardType`：`"C/NO"` 普通、`"C/OP"` 对抗、`"C/CO"` 组合、`"C/SC"` SAN；
`difficulty`：`CoC7DicePool.difficultyLevel.{regular,hard,extreme,critical}`。

## 2. Tidy 5e Sheets（14.3.1）设计规范

实现形态：Svelte 5 组件编译进 `tidy5e-sheet.js`（2.9MB）+ `main.css`（453KB 单行，378 个 `--t5e-*` 变量）+ 45 个 webp 位图徽章/纹理 + 两套随包字体。
`templates/` 只有 4 个空壳 hbs，**没有可用模板**；但 `tidy5e-sheet.js.map` 含 613 个 `sourcesContent`，可完整还原 Svelte 源码（取证方法见调查原始记录）。结论：只能借鉴设计，不能抄结构。

### 2.1 布局（**纠正早前理解**）

真实骨架（`src/sheets/quadrone/actor/CharacterSheet.svelte`）：

```
.tidy5e-sheet.application.actor
├─ header.sheet-header             ← 横幅，高 18.75rem，1px 金底线
│  ├─ .sheet-header-content        ← flex-flow: row-reverse（DOM 顺序与视觉相反）
│  │  ├─ .actor-details-container  ← 名字 h1 + 长休/短休 + 副标题 + 能力值横排
│  │  └─ .actor-vitals-container   ← 10.5rem 方头像 + 压在下缘的深色数据胶囊
│  └─ .tabs-row                    ← 侧栏开关 + tab 条
└─ .sheet-body > .main-content     ← flex row
   ├─ .sidebar（默认负 margin 藏起，展开 17.25rem）← **二级 tab：收藏 / 技能**
   └─ .tidy-tab ×N                  ← 主内容，flex:1 各自滚动
```

**要点**：Tidy 5e 的"能力值"不在左侧常驻栏，而是**横排在顶部横幅里**（AC 盾牌 + 6 项能力 + 先攻 + 专注）；左侧栏是可收起的 **收藏/技能二级 tab**。顶部 tab 条含 9 个主 tab（actions / attributes / inventory / spellbook / features / effects / biography / bastion / journal）。
默认窗口 740×810，`min-width:43.75rem`（700px），无最小高度。
响应式：9 个命名 container query（`actor-sheet` / `sheet-tabs` / `tab-content` / `abilities` / `action-bar` …）+ 18 个匿名断点；能力块在窄容器下降级为 `abilities-size-small/compact`（纯文字条）；表格列按可用宽度自动隐藏。

### 2.3 值得借鉴的关键组件

1. **能力值徽章**：位图徽章（`badge_ability_{light,dark}.webp`，`aspect-ratio:1/1.125`，`background:… top center/contain`）内嵌大号数字；熟练态换另一张图（`_prof`）。**装饰靠位图，布局/状态靠 CSS**。
2. **数据表行**：`border-image` 做中间深两端渐隐的分隔线（比 `border-bottom` 高级）；行悬停时图标位换成骰子（两层图叠放，`opacity` 切换）；单元格右缘竖渐变；表头是金→主题色横向渐变胶囊，文字颜色按背景亮度用 `oklch(from … clamp(...))` 自动反色。
3. **统计方块**：`.cards-container{display:flex;flex-wrap:wrap;gap:.5rem}` + `.card{min-width:10rem;max-width:calc(50% - .25rem)}` + 内联 `value / max`（`.uninput`）+ `±` 按钮。CoC7 的 HP/MP/SAN/LUCK 最该抄这个形态。
4. **进度条纯 CSS**：JS 只写 `style="--bar-percentage:63%"`，条体 `:before{inline-size:var(--bar-percentage);transition:all .5s}`；上限被侵蚀时用 `:after{--bar-adjusted}` 叠第二段。
5. **药丸徽章** `.pill`：1px 描边（亮 grey-70 / 暗 grey-29）、`border-radius:3px`、12px 字号、`min-height:1.5rem`；`.inline-uses` 为 `value / max` 三段 flex。
6. **折叠动画**：`.expandable{display:grid;grid-template-rows:0fr;transition:grid-template-rows .15s}` → `.expanded{grid-template-rows:1fr}`，无需 JS 量高；折叠时不渲染子内容（`deferRendering`）。
7. **tab 条**：`display:flex;justify-content:center;gap:1.5rem`，选中项只变色 + 发光 + 底部 3px 渐变下划线。
8. **可读性**：数字全部 condensed + `tabular-nums`；悬停发光 `text-shadow:0 0 .375rem <gold>` 是 Tidy 的招牌效果。

### 2.4 值得借鉴的交互

- 锁定/解锁贯穿所有组件（`unlocked` 状态）；未锁定时输入框叠在原文本上（`opacity:0`，聚焦才显形）。
- 透明输入框 `.uninput` 就地编辑，支持 `+5` 这类增量输入。
- 悬停换图标（图片 ↔ 骰子）、悬停发光。
- 熟练度四态循环（左键 +1 档、右键 −1 档）——CoC7 可改成"成长标记"。
- 每 tab 独立搜索，同时过滤分区与置顶项。
- 折叠记忆（按 `uuid-tab-location` 存）、侧栏展开记忆、窗口宽高记忆（debounce 持久化到 flag）。
- Ctrl+点击同时打开多个 tab（Truesight）。
- Pins 置顶常用项（按 tab 存 `tabSheetPins`）。
- 长休/短休一键按钮（CoC7 对应"幕间成长/每日 SAN 重置"）。
- 右键上下文菜单 + 行悬停钩子。
- 窄屏三件套：container query 重排、按 rem 阈值降级徽章、表格列自动隐藏。

### 2.5 Tidy 的主题机制（四层，值得照抄）

1. 基座 token（亮色默认）→ 2. `.theme-dark` 覆盖块 → 3. 变体皮肤（parchment / basic）→ 4. **运行时注入**：`insertRule('@layer modules { #<sheetId> { … } }')`，按 `cssText` 精确匹配旧规则实现热替换。
配套：`getForegroundAtContrast()` 按 APCA 自动选前景色，保证任意强调色都可读。

## 3. Foundry 14 中可用能力（本机验证）

- 表注册：`foundry.applications.apps.DocumentSheetConfig.registerSheet(documentClass, scope, sheetClass, {label, types, makeDefault, canBeDefault, canConfigure, themes})`。**`themes` 可声明 dark/light**，Foundry 会按 `设置 → 界面配置 → 颜色方案` 自动给 sheet 加 `themed theme-dark` / `theme-light` 类。
- 基类：`foundry.applications.sheets.ActorSheetV2` + `foundry.applications.api.HandlebarsApplicationMixin`。
- Tab：`templates/generic/tab-navigation.hbs` + `app.getTabs(group, initial, tabs)` / `app.changeTab(...)`。
- DragDrop：`foundry.applications.ux.DragDrop`；Tooltip：`data-tooltip` 属性 + `foundry.applications.ux.TooltipManager`。
- 颜色方案设置：`game.settings.get("core","uiConfig").colorScheme.applications`。

### 4.2 注册（可直接照抄的写法）

```js
const ActorsCollection = foundry.documents.collections?.Actors ?? globalThis.Actors;
ActorsCollection.registerSheet(MODULE_ID, Cls, {
  types: ["character"],
```

### 4.3 它验证过的关键事实

| 事实 | 说明 |
|---|---|
| 投骰入口 | `actor.skillCheck({name}) / characteristicCheck(key) / attributeCheck(key) / weaponCheck({uuid})`；内部即系统 `game.CoC7.macros.skillCheck` 同一条路径 |
| `CoC7RollNormalize` 未导出 | 系统 v3 卡内部用它，但第三方拿不到；**只能走 actor 方法** |
| 系统卡互相干扰点 | `system.flags.locked` 同时是"编辑模式"与系统锁定标志，两张卡共用 |
| 字段拼写坑 | 技能成长标记是 `system.flags.developement`（原拼写），SAN 检查是 `checkFailled`（原拼写），不能"纠正" |
| 富文本入口 | `foundry.applications.ux.TextEditor.implementation ?? globalThis.TextEditor` 三态回退 |
| 脏数据 | 导入卡的 `skill.system.base` 可能是纯数字，需要一次性自愈为 `adjustments.base` |
| 货币档位 | 由 `system.monetary.values[].min/max` 推导信用评级，`formattedMonetaryValue(type)` 有则用 |

### 4.4 它做得好的地方（我们要继承）

- 每个注册独立 try/catch；错误延迟到 `ready` 用 `permanent` 通知，不炸 init。
- **schema 驱动字段枚举**：`system.schema.getField("attribs")?.keys()`，系统加字段自动出现。
- 特征顺序跟随系统设置 `game.settings.get("CoC7","characteristicsOrder")`。
- AE 覆盖检测用 `foundry.utils.flattenObject(document.overrides)`，不碰私有 prepared 字段。
- 能力探测 `typeof document.setHp === "function"` 后才调用；设置门 `developmentEnabled` 双重判断。
- 模板不存对象引用，只存 `data-item-uuid`，点击时 `fromUuid()` 现取，避免陈旧引用。
- 纯函数 view-model 层（`services/*.js`）+ 模板零逻辑，可单测、好维护。

### 4.5 它的债（我们必须避免）

1. 放弃 AppV2 声明式 `actions` / `TABS`，改为每次渲染手写 `querySelectorAll(...).addEventListener(...)` —— 无事件委托、易漏绑定。
2. 30+ 处 `await this.render({parts:["body"]})` 全量重渲，导致不得不加"75ms 防抖 + 手动恢复光标/滚动"等补丁。
3. CSS 变量只在一个 css 里声明、另一个 css 全靠它，文件顺序一变就崩；应拆 `tokens.css` 置顶。
4. 949 行单模板、0 个 partial、185 个 `{{#if}}` —— 应拆 `tabs/*.hbs` + 每 tab 一个 PART。
5. 无拖放（不能从 compendium 拖入、不能排序），系统原生卡反而支持。
6. 两个 sheet 类零共享代码（重复 ~200 行）。
7. 把"系统行为修正"（弹药结算时序补丁，4 个全局 hook）塞进角色卡模组 —— 脆弱且可能双扣。
8. `min-width: 760px` 硬锁 + `@media` 绑视口而非容器。
9. `module.json` 版本与 CHANGELOG 断裂、`verified` 落后。

### 4.6 结论

第三方向 CoC7 注册替代角色卡是成熟做法：**可选并存、不改系统、只用公开 actor 方法**。但实现上要用 AppV2 的现代机制（declarative actions / TABS / PARTS / `_preparePartContext`），并把样式、模板、view-model 分层。

## 5. 关键结论

1. 技术上完全可行：AppV2 + 独立 sheet 类 + 公共 Actor 投骰 API，无需修改系统。
2. Tidy 5e 的"风格"可拆解为：羊皮纸+金色描边+condensed 字体+紧凑表格+悬停操作+左栏能力值/右栏 tab 的布局；这些都能用纯 CSS 复刻。
3. 我们**不复用** Tidy 5e 的代码与图片素材（避免版权与维护耦合），只借鉴设计语言；字体使用 OFL/Apache 授权字体自带。
4. CoC7 的默认 v3 卡功能面较广（8 个 tab、守秘内容、发展系统），新卡必须完整覆盖，否则 GM 会回退。
5. CoC7 用 `system.flags.locked` 做"锁定/编辑"双态，必须先决定新卡是否沿用。
6. **不要给 sheet 加系统 `.coc7` 类**：系统 CSS 有 1958 条 `.coc7` 选择器，会污染我们的布局；只借用 Foundry 核心变量，自带完整皮肤。
7. 交互一律用 AppV2 声明式机制（`DEFAULT_OPTIONS.actions` + `static TABS` + 多 PART），避免 ginzzzu 的手写监听与全量重渲。

## 6. 技能与背景的 CoC-ID 清单（本机取证）

### 6.1 技能 CoC-ID（共 103 个）

来源：`systems/CoC7/lang/cn.json` 中 `CoC7.CoCIDFlag.keys.i.skill.*` 的全集（语言无关的稳定标识）。
技能 Item 的 ID 存放在 `item.flags.CoC7.cocidFlag.id`；`actor.system.skills` 的键为把 ID 中 `.` 换成 `>>`。

6 大类别（供「简表」分组使用，详见设计文档 §15）：
战斗 21 / 调查 42 / 社交 6 / 生存 16 / 技艺 14 / 医疗与精神 4 = 103。

> 注意：`lang/cn.json` 中个别翻译有误/重复（如 `appraise` 译作「取悦」、`language-russian` 译作「德语」），分类必须以 **CoC-ID** 为准，不能按名称文本判断。

### 6.2 背景（Backstory）相关 CoC-ID

系统为规则书背景要素预置了 CoC-ID 键（用于 CoC-ID 编辑器/随机表）：

| CoC-ID | 中文 |
|---|---|
| `rt..backstory-ideology-and-beliefs` | 思想与信念 |
| `rt..backstory-meaningful-locations` | 意义非凡之地 |
| `rt..backstory-significant-people` | 重要之人 |
| `rt..backstory-treasured-possessions` | 宝贵之物 |
| `rt..backstory-traits` | 特质 |
| `rt..backstory-injuries-and-scars` | 伤害与疤痕 |

> 另外恐惧症/狂热症不是背景字段，而是 **`status` 类型物品**（`system.type.phobia` / `system.type.mania`，见 `CoC7.EmptyStatusList = 在此处添加恐惧症/狂热症。`）；系统在物品页「状态」区展示，也能挂 ActiveEffect。
> **设计取舍**：那是"SAN 掉落产生的游戏状态"，而背景页这一栏是人物设定，故本模组用纯文本记录，不联动/不创建 status 物品。

另有 `CoC7.InvestigatorWizard.PersonalDescription = 形象描述`（外貌形象）。

**但系统没有为这些条目提供固定字段或 id**：`system.biography` 只是 `[{title, value}]` 自由数组（`createBioSection/deleteBioSection/moveBioSectionUp/Down` 均按索引操作）。
**「关键链接（Key Connection）」在系统内完全没有对应概念**（全量检索 `connection` 命中 0），必须由模组自行用 flag 实现。

### 6.3 由此确定的数据策略

- 五项背景正文：写入 `system.biography`（原生结构，切回系统卡仍可见）；
- 关键链接：写入 `flags["coc7-tidy-investigator"].keyConnection`（单选）；
- 标题定位：记录 `flags.backgroundTitles`，并内置中/英别名表兜底。

## 1. 背景与目标

### 1.1 为什么现在做

1. 调查员卡已到 0.7.3，七个 tab、编辑态、成长、拖拽等主干功能稳定；基类与样式可以支撑第二张卡。
2. 系统默认 NPC / 生物卡是**纵向折叠面板**（技能 / 战斗 / 库存 / 笔记 / 宏 / 效果 / 守秘），与调查员卡的 Tidy 语言割裂：同一场团里两张卡切换，视觉与操作习惯都要重新适应。
3. KP 使用生物卡的核心动作是**战斗中速读**：HP/MP、护甲、武器伤害、每轮攻击次数、SAN 损失、状态。默认卡首屏只有特性与属性，武器和 SAN 损失要滚动或展开才能看到。
4. `npc` 与 `creature` 在 8.16 中**共用同一套数据模型**（`CreatureSystem extends NPCSystem`，仅默认头像不同），一张卡覆盖两类，增量成本低。

### 1.2 目标

1. **视觉同一语言**：横幅、盾徽、资源条、表格行、金线、悬停操作、亮暗主题、紧凑模式全部沿用调查员卡。
2. **KP 速读**：战斗与 SAN 损失信息进入首屏（横幅 + 默认「战斗」tab），不需要展开面板。
3. **功能覆盖**：默认 NPC / 生物卡的日常操作不因换皮缺失（对照表见 §15），明确不做的项也写清楚原因。
4. **零侵入**：不改 CoC7 系统文件，不抢默认卡，与系统卡 / ginzzzu 等第三方卡并存。
5. **工程量可控**：复用基类与约 70% 样式；新增代码约 600–800 行（含 5 个新模板）、现有文件改动约 150–250 行（§11.1 / §11.4）。

### 1.3 非目标（v1 明确不做）

- 不做 `vehicle`；`container` 已在 0.8.x 补充实现（§19）。
- 不改写规则计算：HP/MP/DB/体格/移动力等一律使用系统派生值。
- 不做受限视图（limited）专用模板：系统 NPC 受限视图只显示头像，价值低，且调查员卡也未实现，v1 保持一致。
- 不做 pulp 规则的「幸运特殊能力」面板（系统 NPC 卡的 LuckSpend 面板仅在特定 pulp 设置下出现，生物卡场景极少用到）。
- 不做自建弹药结算流程：弹药只做「当前子弹 / 弹匣容量」展示与「装填」按钮（调用系统 `system.reload()` / `addAmmunition()`）；射击扣弹仍由系统射击卡结算。
- 不做「死亡检定」按钮：`CoC7ConCheck` 非公开 API（§2.4）。
- 不做 SAN 检定自动结算：通过系统原生 SAN 损失链接卡交给 GM/玩家点击发起（§9.4），不自建掷骰与损失结算。
- 不做移动端专版（窗口最小宽度不崩即可）。
- 不复制 Tidy 5e 的素材与代码；徽章/纹样继续用自制 SVG。

## 2. 数据事实基线

> 全部结论来自本机 CoC7 8.16 安装文件（`system.js` 与 `templates/actors/npc-v2/*`），证据见 [01-调研报告](./01-调研报告.md) 附录。

### 2.1 Actor 类型与卡注册

| 类型 | 数据模型 | 系统默认卡 | 说明 |
|---|---|---|---|
| `character` | CharacterSystem | `CharacterSheetV3`（另有 V2 / 精简 V2 / 精简 V3） | 已有 Tidy 调查员卡 |
| `npc` | **NPCSystem** | `NPCSheetV2`（`classes:["npc"]`，650 宽） | 人形 NPC（邪教徒、警察…） |
| `creature` | **CreatureSystem extends NPCSystem** | `CreatureSheetV2 extends NPCSheetV2`（空类） | 怪物；仅默认头像与模板分支不同 |
| `vehicle` | VehicleSystem | `VehicleSheetV2` | 暂不做 |
| `container` | ContainerSystem | `ContainerSheetV2` | 暂不做 |

结论：**注册一张 sheet，`types:["npc","creature"]`**。卡名统一显示为「生物卡」，内部用 `infos.type` 区分展示（creature 显示「类型」，npc 显示「职业 / 年龄 / 组织」）。

### 2.2 NPC / creature 数据模型（与模板实际使用字段）

| 路径 | 类型 | 说明 |
|---|---|---|
| `system.characteristics.<key>` | `{formula:String, value:Number\|null}` | key = str/con/siz/dex/app/int/pow/edu；**formula 与 character 共用** |
| `system.attribs.hp` | `{value,max,auto}` | auto=true 时上限由系统派生 |
| `system.attribs.mp` | `{value,max,auto}` | 生物常为 null（可不显示） |
| `system.attribs.san` | `{value,max:99,dailyLoss,dailyLimit,auto:true}` | value 默认 null；`max` 受 auto 派生；生物通常不显示 |
| `system.attribs.lck` | `{value}` | 可为 null |
| `system.attribs.mov` | `{value,auto,type}` | type 取 `CONFIG.Token.movement.actions` 键（walk/fly/swim/…） |
| `system.attribs.db` | `{value(String),auto}` | 伤害加值，字符串（如 `1D4`） |
| `system.attribs.build` | `{value,auto}` | 体格 |
| `system.attribs.armor` | `{value(String),notes:Boolean}` | **无 auto 字段**；notes 控制「护甲备注」角标 |
| `system.conditions.<key>.value` | Boolean | criticalWounds / unconscious / dying / dead / prone / tempoInsane / indefInsane |
| `system.biography.personalDescription.value` | HTML | **唯一**的公开描述字段（无七要素数组） |
| `system.description.keeper` | HTML | GM 守秘笔记 |
| `system.special.sanLoss` | `{checkPassed:String\|null, checkFailled:String\|null}` | **系统原文拼写 Failled（双 l）**，不可"纠正" |
| `system.special.attacksPerRound` | String（默认 `"1"`） | 可为公式 `1D3` / `1D4+1` / `@dex` |
| `system.special.movement[]` | `[{value:Number, type:String}]` | 额外移动方式（飞行/游泳…） |
| `system.special.macros[]` | `[{uuid}]` | 骰子宏 |
| `system.infos` | `{type, occupation, organization, age}` | creature 用 type；npc 用后三项 |
| `system.books[]` | 书籍进度 | 与 character 共用定义（生物基本用不到，不展示） |
| `system.flags.locked` | Boolean（**NPC 默认 false**） | 锁定 / 解锁 |
| `system.flags.displayFormula` | Boolean（默认 false） | 特性公式输入模式；系统默认卡**关闭时强制复位 false** |

> `auto=true` 时 HP/MP/SAN 上限与 DB/体格/MOV 由系统派生；固定数值的怪物需先关 auto（编辑态齿轮，§9.2）。
| `system.flags.panel*` | 15 个 Boolean | 系统默认卡的折叠面板状态；本卡不写、不读 |
| `system.config` | `{luckAvoidUnconsciousness…}` | 仅部分派生，不直接展示 |

### 2.3 与 character 的差异（决定哪些 tab 不适用）

| 能力 | character | npc / creature | 对设计的影响 |
|---|---|---|---|
| `biography[]` 七要素 | ✅ 数组 | ❌ 仅 `personalDescription` | 无「背景」tab；改为「描述」 |
| `system.monetary` 货币 | ✅ | ❌ | 物品页去货币条 |
| `system.development` 成长 | ✅ | ❌ | 无「成长」tab、无成长点/成长勾选 |
| `sanityLossEvents` / `backstory` / `notes` | ✅ | ❌ | 守秘页去掉 SAN 事件、遭遇 |
| `special.*`（SAN 损失/攻击次数/移动/宏） | ❌ | ✅ | 新增战斗页与守秘页宏列表 |
| `infos.type` | ❌ | ✅ | creature 身份行 |
| `displayFormula` + formula | 有 formula 字段但无此 UI 流程 | ✅ 系统 NPC 卡提供 | 新增公式模式与批量掷特性 |
| 默认 `locked` | true | **false** | 新建 NPC/生物打开即编辑态（尊重系统行为） |

### 2.4 可用交互 API 与坑（写代码前必须知道）

| 动作 | 可用 API | 备注 / 坑 |
|---|---|---|
| 特性检定 | `actor.characteristicCheck(name, fastForward, options)` | 签名第二参是 **fastForward**；`{event}` 不会被系统转发，**不要依赖 event 修饰键**（Shift 快速投请显式传 `true`） |
| 技能检定 | `actor.skillCheck(nameOrData, fastForward, options)` | 内部 `getItemOrAdd` 会补建缺失技能；传已存在的 `item.name` |
| 武器攻击 | `actor.weaponCheck({uuid}, fastForward)` | 无目标时会弹提示；伤害加值在攻击卡内处理 |
| 属性检定 | `actor.attributeCheck(key, fastForward, options)` | lck/san |
| 特性批量生成 | `actor.rollCharacteristicsValue()` / `actor.averageCharacteristicsValue()` | 只对**已有 formula** 的特性生效；按钮前先 `dispatchEvent(new Event("change"))` 冲掉未提交表单 |
| 攻击次数掷骰 | `new Roll(formula, actor.parsedValues()).roll()` + `roll.toMessage(...)` | 系统卡做法一致；含 `d`/`@` 才可掷 |
| 宏执行 | `fromUuid(uuid)` → `macro.execute({speaker, actor, token, event})` | 列表需自行 `fromUuid` 并过滤 null |
| 宏添加 | 拖 Macro 到卡上：`system.special.macros.push({uuid})` | 系统仅支持拖入；本卡同样做拖入 + 提示 |
| 状态切换 | `actor.toggleCondition(key)`，兜底写 `system.conditions.<key>.value` | 与调查员卡同一实现 |
| 技能改值 | 写 `system.adjustments.experience`（差量） | **`system.value` 不是 schema 字段**，直接写 `system.value` 无效 |
| 武器改值 | `system.range.normal.damage` / `system.skill.main.{id,name}` | v1 不内联，打开武器卡编辑 |
| SAN 损失链接卡 | ✅ `const link = await CONFIG.CoC7Link.documentClass.fromDropData({check:"sanloss", sanMax, sanMin, sanReason}); await link.toChatMessage();` | 系统私有 `CoC7SanCheckCard` 不可直接调用；链接卡由点击者（GM/玩家）走系统自己的检定流程 |
| 死亡检定 | ❌ `CoC7ConCheck` 未公开 | v1 不做按钮 |
| 受限视图 | `actor.isLimitedView`，系统仅渲染头像 | v1 不做专用模板 |

### 4.2 尺寸与响应式

| 项 | 值 |
|---|---|
| 默认窗口 | **780 × 780**（与调查员卡一致，便于双开并排） |
| 最小窗口 | 700 × 500（基类八向缩放，最小尺寸沿用） |
| 横幅高 | 约 370px（头像 152 + 特性 86 + 资源行 60 + 状态/战斗行 32 + tab 42） |
| 内容区 | 780 高时约 410px，武器表可显示 ~8 行（紧凑模式 ~10 行） |
| 窄屏 | `<720px` 特性盾徽缩为 4 列 × 2 行、武器表隐藏「备选技能 / 故障」列（保留射程与子弹/弹容量，装填按钮不丢） |
| 单位 | `rem` + container query，不在根节点写死宽度 |

### 4.3 折叠与记忆

- 横幅不折叠（v1 与调查员卡现状一致；折叠留作后续两卡统一实现）。
- 物品分组折叠、特殊能力折叠：会话内记忆（`Set`，与调查员卡一致）。
- 窗口尺寸按**类名**记忆（`sheetSize` 设置天然按 `constructor.name` 隔离，生物卡独立）。
- 当前 tab 不持久化（与调查员卡一致；需要时后续统一做）。

### 4.4 与调查员卡的布局差异（克制的差异）

## 6. Tab 规格

### 6.1 战斗（默认 tab）

**速览条**（卡片顶部一条，锁定态只读 / 编辑态输入）

| 项 | 字段 | 交互 |
|---|---|---|
| 每轮攻击次数 | `system.special.attacksPerRound` | 编辑态输入框；含 `d`/`@` 时可点击掷骰（聊天卡，私聊自己） |
| SAN 损失 | `special.sanLoss.checkPassed` / `checkFailled` | 编辑态两个输入框；点击生成系统 SAN 损失链接卡（§9.4） |
| 护甲 | `attribs.armor.value` + `notes` | 编辑态输入框；备注开关图标（`notes`） |
| 伤害加值 | `attribs.db.value` | 只在横幅显示，速览条不重复 |

**武器表**（复用调查员卡「简表」的武器表组件）

| 列 | 数据 | 备注 |
|---|---|---|
| 名称 | `item.name` + 图标 | 点击打开武器卡 |
| 使用技能 | `system.skill.main.name` + 实时 `skill.value` | 无技能时显示 `—` |
| 备选技能 | `system.skill.alternativ.name` | 无则留空 |
| 伤害 | `system.range.<normal\|long\|extreme>.damage` | 霰弹枪（`properties.shotgun`）按档位显示多值，每档可掷 |
| 射程 | `system.range.normal.value` | |
| 子弹/弹容量 | `system.ammo` / `system.bullets` | 射击武器显示当前/容量；左侧左轮弹巢按钮装填（单击装满 / Shift 装 1 发），双击数值卸空弹匣 / Shift + 双击卸下 1 发 |
| 故障 | `system.malfunction` | |
| 操作 | 攻击 / 掷伤害 / 打开 | 悬停出现；编辑态另有删除 |

- 编辑态：`+ 添加武器`（`actor.createEmptyWeapon(event)`，必须传 event）；不做内联改伤害/技能，统一打开武器卡编辑（v1 取舍，见 D27）。
- 空态：`还没有武器。解锁后点「+ 添加武器」。`

**特殊能力**（折叠区，只读）

- 数据：`actor.items` 中 `type === "talent"`，名称 + `system.description.value`（富文本 → 纯文本摘要 120 字）。
- 点击打开天赋物品卡；无天赋时不显示该区。
- 编辑态在区块标题右侧提供「+」：创建空白天赋并直接打开其配置卡；也可从物品页「天赋」分组或外部拖入。
- 目的：怪物数据里的「特殊能力」通常以天赋/法术存在，KP 不必去物品页翻找。

**移动方式**

| 行 | 数据 | 编辑 |
|---|---|---|
| 主移动力 | `attribs.mov.value` + `attribs.mov.type` | 值输入（auto 只读）+ 类型下拉 |
| 额外移动 | `special.movement[]` 每项 `{value,type}` | 值输入 + 类型下拉 + 删除 |
| 添加行 | — | 编辑态 `+`，写回整个数组 |

- 类型选项来自 `CONFIG.Token.movement.actions`（walk/fly/swim/burrow/crawl/climb/jump…），按 `order` 排序，显示 `label` 的 i18n 文本。
- 锁定态类型用**纯色标签**展示（`background: var(--c7t-panel-2)` + 正文色文字）：不能继承下拉框的箭头/高光底纹，否则暗色下纹理会把「飞行」等文字盖住。
- 兜底：数组字段不能用表单 name 提交，显式 `actor.update({"system.special.movement": next})`。

### 6.2 技能

| 列 | 锁定态 | 编辑态 |
|---|---|---|
| 名称 | 技能名（专长技能显示 `skillName（specialization）`） | 打开技能卡修改（表内不内联改名，避免与点击投骰冲突） |

| 半值 / 1-5 值 | 显示 | 显示（只读） |
| 操作 | 打开物品卡 | 打开 / 删除 |

- 工具栏：搜索（前端过滤）、排序三态（数值 / 名称 / 自定义）、计数、`+ 添加技能`（编辑态）。

- **无**成长勾选、职业/兴趣/成长点列、罕见技能开关（NPC 无成长体系）。
- 自定义排序拖拽写 `item.sort`（归一化 10/20/30，与调查员卡一致）。
- 空态：沿用 `C7TIDY.Skills.Empty` 文案。

### 6.3 物品

分节（固定顺序）：**护甲 / 书籍 / 法术 / 天赋 / 道具 / 状态**；武器在战斗页，不重复。

| 功能 | 说明 |
|---|---|
| 分组折叠 | 点击标题折叠，会话内记忆 |

## 9. 编辑态与权限

### 9.1 锁定语义

- 直接沿用 `system.flags.locked`：`true` 只读、`false` 可编辑。
- **注意：NPC/creature 的 schema 默认 `locked=false`**，新建生物打开即为编辑态（系统默认卡亦如此）；KP 可在横幅点锁图标锁定。
- `isEditing = isEditable && !locked`，与基类一致。
- 编辑态可见元素：姓名输入、身份输入（描述页）、特性数值/公式、资源输入、派生输入、状态与战斗数值、技能/物品行操作、`+` 按钮、拖拽。
- 锁定态：所有输入变纯文本；特性徽章整体可点投骰；悬停操作按钮仍可用（打开/攻击等）。

### 9.2 auto 只读

| 字段 | 规则 |
|---|---|
| `attribs.hp.max` / `mp.max` / `san.max` | `auto=true` 时只读（tooltip「由系统派生」）；编辑态齿轮可关 auto 后手填 |
| `attribs.build.value` / `db.value` / `mov.value` | `auto=true` 时只读；编辑态齿轮可关 auto |
| `attribs.armor` | 无 auto 字段，始终可编辑；备注 `notes` 用图标开关 |

> auto 齿轮写 `system.attribs.<key>.auto`；固定 HP/MP/SAN 的怪物必须能关 auto（默认卡同款行为，D28）。
> 齿轮在编辑态**常显**（开启时金色），关闭 auto 后仍可点回开启；资源与派生块的齿轮同此逻辑。

### 9.3 公式模式（displayFormula）

- 编辑态横幅顶部出现 `ƒ` 按钮；开启后：
  - 8 个盾徽切换为公式输入（`name="system.characteristics.<key>.formula"`）；
  - 半值 / 1-5 值隐藏（公式未求值时不显示）；
  - 盾徽显示 `ƒ` 角标；仍可点缩写投骰（若已有数值）。
- 数值模式下（默认）：显示「掷特性」「取平均」两个按钮（编辑态且 `!displayFormula`）：
  - 掷特性：`actor.rollCharacteristicsValue()`（逐项掷公式并写 value）；
  - 取平均：`actor.averageCharacteristicsValue()`；
  - 调用前先 `this.element.dispatchEvent(new Event("change"))` 提交未保存的表单。
- 关闭卡时把 `displayFormula` 复位为 `false`（与系统默认卡一致，避免污染数值视图）。

### 9.4 SAN 损失交互（走系统公开链接卡）

- 事实：
  - 系统私有类 `CoC7SanCheckCard` **不可直接调用**；
  - 但系统在 `init` 注册了公开的 `CONFIG.CoC7Link = {documentClass: CoC7Link}`，并提供 `@coc7.sanloss[...]` enricher；
  - `CoC7Link.fromDropData()` + `.toChatMessage()` 会发出一条系统原生「SAN 损失链接卡」，点击者（GM 对选中 Token / 玩家）由系统自己执行 SAN 检定。
- v1 方案（推荐）：
  1. 横幅 `SAN 损失` 胶囊显示 `通过值 / 失败值`（如 `0/1D6`）；
  2. 点击时读取 `CONFIG.CoC7Link?.documentClass`，调用
     `const link = await fromDropData({ check: "sanloss", sanMax: checkFailled, sanMin: checkPassed, sanReason: infos.type || actor.name }); await link.toChatMessage();`；
  3. 能力探测失败（老版本系统/API 变更）时回退：发送一条不掷骰的提示卡「{生物名}：SAN 损失 通过 0 / 失败 1D6」。
- 不写 Actor 数据、不复制系统内部逻辑；检定流程完全由系统承担。
- 兼容备注：若系统未提供 `CONFIG.CoC7Link`，只保留回退提示卡；不尝试引用私有类。

### 9.5 AE 修正

- 只读展示直接用 `actor.system` 的派生值（AE 已应用），数值正确。
- 「被 AE 修改」角标需要 view-model 产出 `sourceValue / activeEffect*` 字段（现有 `view-data.js` 未提供）→ 列为 **M4 增强项 ⏳**；v1 不做不影响数值正确性。
- 编辑态 v1 直接写 `system.*`（与调查员卡一致）；AE 同时生效时以系统数据为准，不做 source 回写。

### 9.6 GM 与受限

- 守秘 tab 仅 GM 可见；守秘笔记遵循锁定（锁定态只读、解锁可编辑，与调查员卡现有实现一致）。
- 非 owner 玩家：走锁定态；不渲染守秘 tab。
- v1 不实现 limited 模板（系统仅有头像页）。

### 11.2 Sheet 类骨架（设计）

```js
export class Coc7TidyNpcSheet extends Coc7TidyBaseSheet {
  static DEFAULT_OPTIONS = {
    classes: ["coc7-tidy", "sheet", "actor", "c7t-npc"],
    position: { width: 780, height: 780 },
    window: { resizable: true },
    form: { submitOnChange: true, closeOnSubmit: false },
    actions: {
      ...Coc7TidyBaseSheet.COMMON_ACTIONS,        // 上移的通用 action
      toggleFormulaMode, rollCharacteristics, averageCharacteristics,
      rollAttacksPerRound, sanLossReminder,
      addMovement, removeMovement,
      executeMacro, removeMacro,
    },
  };

  static TABS = {
    primary: {
      initial: "combat",
      labelPrefix: "C7TIDY.Tabs",
      tabs: [
        { id: "combat", icon: "fa-solid fa-crosshairs" },
        { id: "skills", icon: "fa-solid fa-dice-d20" },
        { id: "inventory", icon: "fa-solid fa-suitcase" },
        { id: "description", icon: "fa-solid fa-book-open" },
        { id: "keeper", icon: "fa-solid fa-feather" },
        { id: "effects", icon: "fa-solid fa-bolt" },
      ],
    },
  };

  static PARTS = { body: { template: TEMPLATES.npcSheet, scrollable: [".c7t-scroll"] } };

  async _prepareContext(options) {
    const context = await super._prepareContext(options);
    context.isCreature = this.document.type === "creature";
    context.npc = prepareNpcView(this.document);   // identity/combat/movement/talents
    context.weapons = prepareWeapons(this.document);
    context.inventory = preparePossessions(this.document, { types: NPC_ITEM_TYPES });
    context.skillView = prepareSkillView(this.document, { sort: this.skillSort });
    context.description = await enrichNpcDescription(this.document);
    context.macros = await prepareMacros(this.document);
    return context;
  }

  _onRender(context, options) {
    super._onRender(context, options);           // 基类已装通用监听
    this.#installNpcListeners();                 // 仅生物卡特有的少量监听
  }
}
```

### 11.5 兼容守则（沿用调查员卡 + 新增）

1. 只用公开 Actor API；调用前能力探测，失败只提示不崩。
2. **不依赖** `CoC7SanCheckCard` / `CoC7ConCheck` 等私有符号；SAN 损失只走公开注册的 `CONFIG.CoC7Link`（失败回退提示卡）。
3. `special.sanLoss.checkFailled` 保留系统拼写；`attribs.armor` 无 `auto` 字段。
4. 技能改值写 `system.adjustments.experience`（差量），不写 `system.value`。
5. 数组字段（`special.movement` / `special.macros`）显式整体写回，不用表单 name。
6. 模板不持有文档对象，只读视图模型；所有富文本渲染走 `TextEditor.implementation` 三态回退。
7. 窗口根类固定 `coc7-tidy` + `c7t-npc`，**不加** `npc` / `creature` / 系统 `.coc7` 类（避免系统选择器命中）。
8. `displayFormula` 关闭卡时复位 false。
9. 自定义状态只进 `flags["c7t"]`；本卡 v1 不新增自定义 flag（技能排序用现有 world 设置）。

### 11.6 性能

- 生物卡列表规模小（技能通常 <20、物品 <15、宏 <5），继续**单 PART** 全量渲染可接受；不为多 PART 重构（D24）。
- 富文本在 `_prepareContext` 一次性 enrich；守秘笔记仅在 GM 且 tab 可见时处理。
- 宏列表 `fromUuid` 逐个解析，数量少；失效 uuid 不抛错。
- 拖拽/搜索/折叠不触发全量 render（与调查员卡同一实现）。

## 19. 补充：容器卡（`container`）

### 19.1 数据事实

`CoC7ModelsActorContainerSystem` 极简：

| 字段 | 类型 | 说明 |
|---|---|---|
| `system.description.value` | HTML | 玩家可见描述 |
| `system.description.keeper` | HTML | GM 守秘笔记 |
| `system.flags.locked` | Boolean（默认 false） | 锁定 / 解锁 |
| `system.flags.panel*` | 5 个 Boolean | 系统默认卡的折叠状态；本卡不读写 |

- 没有特性、属性、状态、技能、宏、货币；只有一个 `description` + 内嵌 Item。
- 默认卡：672×765，tab = 内容 / 描述 / 守秘（GM）+ 锁定按钮；允许拖入 `book / item / spell / weapon / armor`；库存可显示全部 7 类物品。
- 默认头像 `icons/svg/chest.svg`。

### 19.2 本卡设计

- 独立 sheet：`Coc7TidyContainerSheet`，注册 `types:["container"]`，默认 660×720；
- **紧凑横幅**：96px 头像、名称、`容器 · N 件`、按类型汇总的物品计数芯片；无特性/资源区；
- 4 个 tab：**内容（默认）** / 描述 / 守秘（GM）/ 效果；
- 内容页：按 武器/护具/书籍/法术/天赋/道具/状态 分节，折叠、数量编辑、编辑态拖拽排序、分组 `+`；空分组仅在编辑态显示（便于添加）；
- 描述 / 守秘：prose-mirror；守秘仅 GM 可见；容器没有状态数据，因此**不显示「清除状态」**；
- 复用基类的搜索/右键/拖拽/数量监听；不新增自定义 action；
- 窗口类 `c7t-container`，样式 `styles/container.css`。

### 19.3 与系统容器卡的差异

| 项 | 系统默认卡 | 本卡 |
|---|---|---|
| 布局 | 672×765，双 PART（header + tabs） | 660×720，单 PART，紧凑横幅 |
| tab | 内容 / 描述 / 守秘 | 内容 / 描述 / 守秘 / 效果 |
| 物品分组 | 折叠面板 | 分节 + 折叠 + 拖拽排序 + 数量 |
| 锁定 | 图标 tab | 横幅右上锁按钮 |
